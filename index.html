01 Core Architecture

Execution without governance is reckless. DeskFlow governs.

Uncontrolled agentic execution risks severe capital depletion, venue misrouting, and unverified fills. DeskFlow implements an institutional four stage execution lifecycle before any order touches exchange rails.

01 — PARSE AND GOVERN

Mandate Validation

Extracts order intent dynamically from natural language. Enforces cash only execution, rejects leverage or futures, and caps parent order capital at ten dollars.

02 — PRICE AND ROUTE

Cross Venue Depth

Queries Binance public order book depth against Convert quotations. Selects the optimal venue with strict fee isolation and zero fabricated quotes.

03 — REQUIRE CONFIRM

Explicit Authorization

Issues an unconfirmed pretrade ticket with a unique parent order identifier. Execution remains strictly halted until an operator inputs the exact approval token.

04 — RECONCILE AND AUDIT

Blotter Accounting

Calculates implementation shortfall in basis points against decision mid, separates exchange fees, and appends the fill record to an immutable blotter.

02 Binance Agent OS

Built entirely on Binance infrastructure.

03 Tool Registry

Standard Model Context Protocol tool interfaces.

AI agent orchestrators connect to DeskFlow over standard input and output. Any client supporting the Model Context Protocol can invoke these four core clerk tools.

Tool Name Input Arguments Operation and Return Shape
deskflow_price_order {"order_text": string} Parses natural language prompt, checks mandate limits, queries live depth, and returns pretrade ticket
deskflow_confirm_execution {"po_id": string, "confirm_token": string} Verifies authorization token, executes order on selected venue, computes shortfall, appends to blotter
deskflow_inspect_blotter {} Reads the complete immutable blotter audit trail with historical execution shortfall metrics
deskflow_verify_mandate {} Returns active governing constraints including size caps, permitted venues, and confirmation mandates
04 Implementation Guide

How developers and agents use DeskFlow.

DeskFlow provides three distinct access methods depending on operator requirements: as a client attached Model Context Protocol server, a standalone command line clerk, or an automated verification suite.

Method 1 · Attach to Claude Code or Agent OS Client MCP PROTOCOL 
# Step 1 · Connect official Binance Agent OS gateway
claude mcp add binance-mcp-server --transport http https://agent.binance.com/mcp/agentic

# Step 2 · Connect DeskFlow execution clerk
claude mcp add deskflow -- python deskflow.py mcp

# Step 3 · Prompt your agent naturally
Operator: "Buy 5 USD BNB. Cash only."
DeskFlow: Emits PO_001 pretrade ticket with decision mid and asks for CONFIRM PO_001.
Operator: "CONFIRM PO_001"
DeskFlow: Executes on Binance Spot, isolates fee, and returns glowing receipt card.
